# MagicTwin 设计理念

- 日期：2026-07-07
- 文档类型：设计理念提炼
- 定位：把设计哲学收敛成一页可反复回看的"为什么这么设计"。

---

## 一、北极星：一句话定位

> **MagicTwin = 人 + 数字分身（Twin）+ 工具 Agent 在同一块任务看板上协作的团队 AI 数据工作台。**

核心交互链路是 **User → Twin → Agents**：

- 你对自己的**数字分身**（Twin）说话；
- 分身理解你、维护上下文与记忆、去**协调专业工具 Agent** 干活；
- 遇到高风险动作，分身**回来请你确认**。

数据分析是旗舰垂类，底座是通用的。

## 二、贯穿全局的十条设计哲学

### 1. G3 文件优先：真相源与派生索引严格分离

- **命题**：文件系统是**唯一真相源**；任何缓存/索引都是**可重建的派生物**。
- **为什么**：真相落在人类可读、可 diff、可 grep、可备份的文件里，系统就永远有"退回到文件"的确定性底线；派生物可以随时丢弃重建，不会成为不可信的第二真相。
- **如何落地**：任务空间 `tasks/{tid}/` 下所有数据以文件形式持久化（conversation.jsonl、decisions.jsonl、sql/、data/、STATE.md），绝不依赖外部数据库。

### 2. 统一抽象，绝不做第二套运行时

- **命题**：**Twin 与工具 Agent 是同一抽象的两种 `kind`**。Twin = 用户私有的 Agent + 若干特权（编排其他 Agent、发起审批、读写用户空间、导航）。
- **为什么**：如果 Twin 和 Agent 各跑一套运行时，多方协作就要在两套上下文之间做胶水，复杂度和 bug 面翻倍。统一抽象让它们天然共存于同一个编排循环、同一套上下文组装、同一种 `agent.md` 与记忆格式。
- **如何落地**：Twin 落在 `users/{uid}/twin/`，工具 Agent 落在 `agents/{aid}/`，但都复用编排引擎、`agent.md` 手册、记忆格式；在对话里都是一等发言者，Twin 额外是编排者。

### 3. 空间即边界：隔离与复用的刻意张力

- **命题**：所有持久数据落在**四层空间**——任务空间、Agent 空间、用户空间、团队/项目空间——每层有明确的归属、生命周期与隔离边界。
- **为什么**：多人 + 多 Agent + 多任务同台协作，最大的风险是"记忆/文件串味"。用空间把隔离做成结构性的默认，把复用做成显式的、可审计的动作，才能既安全又不失协同价值。
- **如何落地**：
  - **任务空间** `tasks/{tid}/`：对话、文件、过程记忆，仅参与者可读，**不跨任务**；
  - **Agent 空间** `agents/{aid}/`：手册/技能团队共享，但情景记忆**按用户分区**；
  - **用户空间** `users/{uid}/`：Twin 画像与长期记忆，默认仅本人及本人 Twin 可读；
  - **团队/项目空间** `teams/{tid}/…`：共享文件/知识/产物，按 Team 或 Project 隔离。

### 4. 记忆是平台内核：候选 → 审批 → 晋升，绝不直接跨层写

- **命题**：**没有任何主体可以直接写更高层空间**。跨层的一切长期记忆/产物，都必须走"候选 → 审批 → 晋升"。
- **为什么**：记忆决定了 AI 未来的行为。如果 Agent 能悄悄把一条经验写进团队共享空间，就等于让一次对话污染所有人的未来。把晋升做成显式、原子、可审计的闸门，是信任的地基。
- **如何落地**：每日进化引擎从任务对话中归纳经验，生成候选写入 Agent 空间的 `memory/LEARNINGS.md`，用户可随时人工编辑覆盖。

### 5. 安全先于智能：治理是一等公民，不是补丁

- **命题**："能力"永远排在"治理"之后放量。
- **为什么**：一个能自动执行、能跨空间读写、能花钱的系统，一旦失控代价极高。宁可慢一点、保守一点，也不要"看似有、实则无"的安全错觉。
- **如何落地**：
  - **高风险动作**（写文件/跑命令/发消息/付费/固化记忆/跨空间读取）必走 **HITL + 审计**；
  - **一键暂停**全局执行；
  - **数据查询只读**：白名单只允许 `SELECT`/`WITH...SELECT`，从工具层杜绝写操作。

### 6. 主动性有边界：只提议，不越权

- **命题**：Agent 的主动性最多到"提议 / 请求确认"，**绝不替用户做最终高风险决策**。
- **为什么**：主动是价值（自动推进计划、盯盘、周期任务），也是风险（打扰、烧钱、擅自行动）。边界画在"提议"上，既释放主动性，又守住人的最终控制权。
- **如何落地**：
  - 低风险确认 Twin 基于用户偏好代答，高风险升级回来问用户；
  - 有界多跳编排：Twin 是**唯一 leader**，多跳必须有界 + 防环 + 预算 + 治理，不引入 Agent 对等自由对话。

### 7. 保守灰度：新机制默认关，关时零行为变化

- **命题**：每个新机制都用特性开关灰度，**保守默认关**，且关闭时**零行为变化**。
- **为什么**：一个持续演进的系统，必须保证"加了新东西不破坏旧行为"。默认关 + 零行为变化，让每次演进都可回退、可灰度。
- **如何落地**：新功能默认关闭，测试"关一条 + 开一条"，其中"关"那条断言与旧行为一致。

### 8. 状态优先的人机界面

- **命题**：界面以**状态**为主角，而非以功能菜单为主角。
- **为什么**：人机协作现场，用户最关心的是"现在到哪了、卡在哪、要不要我确认"。让状态说话，认知负担最低。
- **如何落地**：任务 6 态（待办/执行中/待确认/已完成/报错/已暂停）；Agent 三件套（状态 + 一句话能力 + 正在做什么）；产物 3 态（草稿/已确认/已发布）且**渐进展开**。

### 9. 降级不阻塞，外部依赖走可注入接缝

- **命题**：缺失任何外部 CLI/服务都**不阻塞启动**；真实客户端通过可注入接缝封装。
- **为什么**：平台依赖 LLM 网关、数据查询等外部系统。若任一缺失就无法启动或测试，开发和部署就寸步难行。
- **如何落地**：缺 LLM key → 提示配置但不崩；数据查询未配置 → 演示模式返回示例数据；真实调用点是 monkeypatch 友好的接缝。

### 10. 借鉴而非搬运

- **命题**：从开源项目大量借鉴设计范式，但**用自有代码按本项目约定重写**，不拷贝源码。
- **为什么**：站在巨人肩上能少走弯路，但直接搬运会带进不兼容的契约、样式、依赖方向，甚至许可证风险。取其"信息架构与交互范式"，落到自己的文件优先 / 中文注释体系里，才是可维护的。

## 三、三个关键抽象

### 抽象一：统一 Agent（Twin 是特权 Agent）

Twin 与工具 Agent 共用 `agent.md` / 记忆格式 / 编排引擎。差别只在归属与特权：

| 维度 | 工具 Agent（kind=tool） | Twin（kind=twin） |
|---|---|---|
| 归属 | 团队/平台共享 | 用户私有（1 user ↔ 1 twin） |
| 记忆 | 按用户分区 + 团队共享 | 用户长期记忆（偏好/决策/上下文） |
| 特权 | 无 | 编排 Agent、发起审批、读写用户空间、导航 UI |
| 在对话里 | 一等发言者 | 一等发言者 + 编排者 |

`agent.md` 是"始终注入"的操作手册，含角色定位、适用/不适用任务、工作方式、输入输出、失败处理、约束边界；Twin 多"编排原则"和"不可越权边界"两节。

### 抽象二：四层空间

```text
users/{uid}/        用户空间：Twin 画像 + 长期记忆（私有）
agents/{aid}/       Agent 空间：手册/技能团队共享，情景记忆按用户分区
teams/{tid}/…       团队/项目空间：共享文件/知识/产物（按 Team/Project 隔离）
tasks/{tid}/        任务空间：对话/文件/过程记忆（参与者可读，不跨任务）
```

优先级：任务级 > 参与者空间 > 用户 > 项目 > 团队（越具体越优先），但记忆是"叠加 + 标注来源"，不是配置覆盖。

### 抽象三：记忆晋升闭环

```text
对话中沉淀经验
  → 每日进化引擎归纳（engine/evolve.js）
  → 写入 agents/{aid}/memory/LEARNINGS.md（候选）
  → 用户/管理员审阅（可随时人工编辑覆盖）
  → 运行时注入 system prompt
```

## 四、治理与安全模型

治理不是某个模块，而是一张贯穿全栈的网：

- **HITL + 审计 + 一键暂停**：高风险动作进审批队列；所有工具调用落审计。
- **数据查询只读**：白名单只放 `SELECT`/`WITH...SELECT`，拒 DDL/写，从工具层杜绝写操作。
- **LLM key 只在服务端**：不下发到浏览器。
- **用户画像绝不进 Git**：`profile.md` 在 `.gitignore`。

一个提纲挈领的口号是：**内容隔离、审计可见**。

> **一句话收束**：MagicTwin 用"文件优先的确定性"托住底，用"统一 Agent + 四层空间 + 记忆晋升"搭起协作骨架，用"治理优先 + 保守灰度 + 主动有边界"守住信任，用"借鉴而非搬运 + 决策可追溯 + 可重建即可信"保证它能长期、安全地演进。
