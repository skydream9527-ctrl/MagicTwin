# 项目构想与设计（v2）

> 一个能在 Mac 上直接启动的网页 Demo：你给一个数据分析/研究目标，**数字分身（Twin）代替你**去驱动**专业工具 Agent**——它真连接数据源查真实数据、真跑代码分析；Twin 替你回答过程中的确认项、把关产出质量，最后把成果交付给你。全程你可随时进工作空间审阅完整对话、过程产物与决策记录。

本文是 v2：在 v1 构想基础上，实现了核心闭环真实跑通，对齐统一 Agent 抽象哲学，并支持多 Agent 并行协作。

---

## 一、定位：可运行的多 Agent 协作切片

项目的北极星是：**人 + 数字分身（Twin）+ 工具 Agent 在同一块任务看板上协作的 AI 工作台**，核心链路是 **User → Twin → Agents**。

这个项目不重做整个平台，而是把那条主链路里**最有说服力的一段**做成一个真实可跑的开源/本地可部署切片：

> **Twin 代替用户，驱动多个专业工具 Agent 完成一次真实的取数 + 分析 + 排版 + 交付，用户全程可旁观、可回溯、可随时接管。**

数据分析是旗舰演示垂类，支持真连数据平台查询，也支持本地代码沙箱执行，不依赖特定内部系统，可适配任意 OpenAI 兼容的模型网关。

## 三、三方角色（统一 Agent 抽象）

设计哲学：**Twin 与工具 Agent 是同一抽象的两种 `kind`**，统一运行时，不做两套实现：

| 角色 | kind | 定位 | 职责 | 边界 |
|---|---|---|---|---|
| **用户（你）** | — | 目标设定者 & 最终验收人 | 给目标、随时审阅、验收、拍板被升级上来的高风险决策 | 不盯每一步细节 |
| **Twin Agent（数字分身）** | twin（特权编排者） | 用户的代理人 / 唯一 leader | 理解意图、拆分任务、派发给对应工具 Agent、**替用户回答低风险确认项、检查产出、必要时打回重做、高风险决策上报用户**、最终汇总交付 | 只提议不越权；高风险回来问用户 |
| **工具 Agent（专家）** | tool | 各领域专业执行者 | 按 SOP 完成 Twin 派发的子任务，查数据/写代码/排版/分析，遇到不确定/需确认点上报 Twin | 不替用户/Twin 拍板；只读/沙箱执行，不越权操作 |

**关键**：所有工具 Agent 的「甲方」都是 Twin，不是用户本人。这是多 Agent 编排的核心设计。

## 四、核心机制（架构灵魂）

### 4.1 Twin 唯一编排 + 有界多跳

不是「用户问、Agent 答」，而是 **Twin 站在用户立场**驱动多个工具 Agent、逐步验收：结果口径对不对、有没有坑，不满意就打回重做。编排是**有界**的（防环、步数/Token 预算上限、上下文自动压缩），不引入 Agent 之间自由对话，所有通信都经过 Twin 路由。

支持三种协作模式：
- **串行派发**：单 Agent 一步步执行，适合简单任务
- **fanout 并行派发**：多个互不依赖的子任务同时派发给不同 Agent，并行执行，大幅提速
- **圆桌讨论模式**：多个专家 Agent 各自给出观点，Twin 汇总冲突点形成共识结论

### 4.2 确认项分级代答机制（主动性有边界）

每个工具 Agent 的 SOP 天然存在「确认门」——命题澄清、口径确认、方案选择、结果校对……这些确认项由 Twin 基于信任等级和风险分级自动处理：

- **低风险确认**（选哪个口径、下钻哪个维度、校对 SQL）→ **Twin 基于上下文与历史经验直接代答**，任务不被打断
- **高风险 / 拿不准**（超出目标范围、高成本查询、可能产生副作用）→ Twin **升级回来问用户**，进待确认队列

> 最爽的体验：大部分确认门 Twin 自动扛下来了，用户没被打扰，但每个代答都留痕可查，信任逐步建立。

### 4.3 通用工具层架构

所有 Agent 可调用的工具统一收敛到通用工具层，扩展工具只需注册，无需修改编排逻辑：

| 工具 | 能力要求 | 说明 |
|---|---|---|
| `query` | query | 只读 SQL 查询，自动校验只读安全 |
| `execute_python`（别名 `execute`） | execute | 沙箱执行 Python 代码，支持数据分析、可视化 |
| `read_skill` | 全员可用 | 读取本地技能文档/SOP |
| `write_file` | 全员可用 | 将结果/报告写入任务产物区 |
| `now` | 全员可用 | 获取当前时间 |

### 4.4 模型智能精简

大模型网关往往返回上百个模型，用户无法选择。系统自动按规则精简：
- 每个供应商最多保留 3 个模型
- 供应商自家模型优先，转售模型补位
- 版本号从新到旧排序，优先基础款、规范命名
- 自动过滤非对话模型（语音/视觉/向量）
- 已保存的模型选择、推荐模型强制保留，不会从下拉列表消失

### 4.5 信任闭环与经验沉淀

- **信任等级**：基于决策正确率、用户反馈、任务完成质量动态调整 Twin 的信任等级，L1 全手动确认 → L4 全自动代答
- **风险矩阵**：可配置哪些信号必须升级（比如"删除""全量""生产"等关键词）
- **经验包机制**：任务完成后自动提取候选经验，用户审核通过后晋升为个人经验，优质经验可共享到团队，形成可复用的最佳实践库

### 4.6 文件作为唯一真相源

工作空间持久保留整个过程，**所有内容落盘为文件**，不依赖内存状态：

```
workspace/
├── tasks/{tid}/
│   ├── events.jsonl       # 所有事件流：对话/工具调用/决策，全程可回放
│   ├── decisions.jsonl    # Twin 替用户做的所有决定，含理由和反馈
│   ├── sql/               # 所有执行过的 SQL 原文
│   ├── artifacts/         # 任务产物：报告/图片/数据文件
│   └── meta.json          # 任务元信息：状态/模型/团队/耗时/Token用量
├── twin/
│   ├── persona.md         # Twin 人设
│   └── knowledge/         # Twin 知识库与通用技能
├── agents/                # 各工具 Agent 定义与专属知识
└── experience/            # L1/L2/L3 经验包存储
```

用户随时进来都能看懂：谁说了什么、跑了什么、拿到什么结果、Twin 替自己做了哪些决定。

## 五、典型协作流程示例

1. **用户 → Twin**：「看看产品最近一周核心指标有没有异常，帮我定位下，下班前给结论。」然后**走开**。
2. **Twin** 复述并锁定命题，拆分两个独立子任务：「① 近 7 天核心指标趋势 + 环比；② 按核心维度拆分准备下钻数据」，使用 `fanout` 并行派发给数据 Agent 和代码 Agent。
3. **数据 Agent（确认门）**：「时间口径按自然日？主表用核心指标宽表、DAU 口径去重对吗？」
4. **Twin 代答**（不打扰用户）：「对；按自然日、标准口径；日期分区用整型过滤。」*(理由：用户一贯看自然日、认标准口径)*
5. **两个 Agent 并行执行**：数据 Agent 查真实数据库，代码 Agent 准备分析脚本。
6. **数据 Agent 完成**：返回趋势数据，环比 -9%，触发波动阈值，自动下钻维度。
7. **代码 Agent 完成**：加载数据，发现某维度下跌最明显，返回初步分析结果。
8. **Twin 汇总验收**：数据自洽、口径一致，结论可信。
9. **Twin 派发给排版 Agent**：把结果整理成结构化报告。
10. **Twin → 用户（交付）**：「近 7 天核心指标环比 -9%，主要拖累是某渠道/某功能。附：趋势图 + 我替你定的 3 个口径决定 + 建议下一步排查方向。」
11. **用户**稍后回来看交付；**点开工作空间**能回看全部对话、真实 SQL、代码与结果。

> 高光：并行执行 + 自动代答确认项，**全程没打扰用户**，但一切可回溯、可审计。

## 六、技术架构

```
浏览器（工作空间 UI，状态优先）
     │  SSE 流式：实时推 Twin / 工具 Agent 的对话与工具调用
     ▼
本地 Node.js 服务（后端，零额外依赖）
     ├── 编排引擎：驱动 Twin ⇄ 工具 Agent 有界多轮协作
     │     ├─ 确认项代答/打回/升级/交付
     │     ├─ fanout 并行派活与结果聚合
     │     └─ 上下文自动压缩（防 Token 溢出）
     ├── 通用工具层：统一收敛所有工具能力，可扩展
     │     ├─ query → SQL 只读查询
     │     ├─ execute_python → 沙箱代码执行
     │     ├─ read_skill/write_file/now → 基础工具
     │     └─ 可扩展任意自定义工具
     ├── 领域模型：
     │     ├─ 信任/风险分级系统
     │     ├─ 经验包沉淀与晋升
     │     ├─ 模型列表智能精简
     │     └─ 任务持久化与产物管理
     └── 静态前端：原生 HTML/CSS/JS，零构建，开箱即用
     ▼
任意 OpenAI 兼容 LLM 网关 + 数据源/沙箱
```

设计原则：
- **降级不阻塞**：模型不可用 → mock 模式；数据查询不可用 → 提示用户，不崩溃
- **安全默认**：SQL 默认只读，沙箱隔离，敏感配置不暴露给前端
- **零构建启动**：前端原生 JS，后端纯 Node，`npm start` 一键启动，无需打包编译
- **可扩展**：新增工具/Agent 只需配置文件+提示词，无需修改核心编排代码

## 七、快速开始

1. 配置模型网关 API Key（支持任意 OpenAI 兼容接口）
2. （可选）配置数据查询引擎、Python 沙箱
3. `npm install && npm start`
4. 浏览器打开 http://localhost:3333 即可使用
