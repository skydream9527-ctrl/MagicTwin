## 二、事件与留痕

对齐「文件为唯一真相源」：每一次判定都要能被复盘，否则无法验证这套标准是否真的在执行。

建议新增事件（追加式，向后兼容现有 SSE 与 `conversation.jsonl`）：

| 事件 | 何时发 | 关键字段 |
|---|---|---|
| `guardrail_check` | 开场前护栏判定 | `hits[]`、`decision`（open / decline）、`reason` |
| `focus_set` | 设定 / 切换焦点 | `focus`、`criteria`、`round` |
| `gain_tag` | 每次发言判定增量 | `gain`（E / A / R / C / 0）、`evidence_level`（A~D）、`speaker` |
| `contention` | 登记 / 更新 / 关闭分歧 | `id`、`kind`（fact / caliber / value）、`status`、`why_open` |
| `round_check` | 每轮末三问判定 | `q1_open`、`q2_gain`、`q3_budget`、`decision`、`reason` |
| `review`（验收） | 每次验收 | `verdict`（pass / rework）、`criteria_ids[]`、`attempt` |
| `appeal` | 申辩与裁定 | `by`、`grounds`、`ruling`（accept / reject） |
| `close` | 收口 | 见 [DC-22](./03-收口与终止.md) 全字段 |
| `abort` | 终止 | `reason`、`partial_result`、`resume_condition` |
| `review_due` | 到期回看扫描命中 | `tid`、`review_at`、`questions[]` |
| `review_result` | 回填判定 | `verdict`（成立 / 部分成立 / 推翻）、`gap_reason`、`lesson`、`next`（R1/R2/R3） |
| `reopen` | 重议开场 | `trigger`（T1~T6）、`scope`（R1/R2/R3）、`inherits[]`、`budget` |

落盘：与 `decisions.jsonl` 并列新增 `tasks/{tid}/discussion.jsonl`（判定流水），不改现有文件格式。前端可分轮渲染，并展示「这一轮为什么继续 / 为什么收 / 为什么重开」。

## 四、实测暴露并已修掉的三个问题

真实跑通（真实 LLM + 真实 kyuubi 取数）后才发现的，写在这里避免重犯：

| 问题 | 现象 | 处置 |
|---|---|---|
| 「无分歧」判早了 | 第一位专家发言后即判 Q1=否 → 直接收口，其余专家全程没上场 | Q1 增加全员发言门槛：未发言人数 > 0 时即使无分歧也 CONTINUE，并点名还没发言的人 |
| 收束后连续小结不收口 | 合格小结不计空转后，主持人连做 5 次 summarize 拖着不 close | 同轮第二次小结记空转；CONVERGE 指令区分「已小结过」，已小结就要求直接 close |
| 回看日期落在过去 | 模型拿数据日期（T-2）当 `review_at`，结论一落地就被扫成到期 | `review_at <= 今天` 视为缺失，要求重写；反复缺失按默认间隔兜底并留痕 |

## 四、验收标准

**推进与收束**
- [ ] 任一场讨论都能回答「每一轮为什么开、为什么收」——`discussion.jsonl` 里有对应 `focus_set` / `round_check`。
- [ ] 无判定标准的焦点无法开轮（引擎拒绝并要求补 `criteria`）。
- [ ] 连续 2 轮空轮必定进入收束，不依赖模型自觉。
- [ ] 事实 / 口径分歧不会被「再辩一轮」，而是自动转取数或查规则；价值分歧一定升级到决策人。
- [ ] 异动类议题在定位四件事完成前不产生归因发言。

**收口质量**
- [ ] 收口产出含事实 / 判断 / 行动三层，事实带证据等级，C/D 级不出现在 `facts[]`。
- [ ] `consensus[]` 每条可追溯到一次明确确认；否则自动降级为「当前建议」。
- [ ] `next_steps[]` 三要素齐全或用 `[待确认]` 占位，无虚构承诺。
- [ ] 分歧不为空时不影响交付（C1+C3 即可定案）。

**审查线**
- [ ] 同一交付物第 3 次打回被引擎拒绝，Twin 必须三选一并留痕。
- [ ] 每次打回都引用了 `pc_*` / `rt_*` 条目；无引用的判无效并要求重写。
- [ ] Agent 申辩被采纳时，判据沉淀进 `LEARNINGS.md` 或验收清单。

**重启与重议**
- [ ] 每个收口结论都有 `restart_condition` 与 `review_at`；缺任一则收口不合格。
- [ ] 到期扫描能生成 `review_due`，并产出三态回填 `review_result`。
- [ ] 重议按 R1/R2/R3 决定继承范围；R3（口径变更）会重验事实层。
- [ ] 新结论带 `supersedes` 与量化差异说明；旧结论保留且标 `superseded_by`。
- [ ] 同一议题第 3 次重议被拒绝，需决策人显式批准或转长期观察项。

**多用户**
- [ ] 非决策人的指令不会改变焦点或触发收口。
- [ ] 高风险确认项超时后场处于「挂起」而非「默认同意」。
- [ ] 讨论记录全场可见，但情景记忆按 `uid` 分区；跨用户确认项一律升级本人。

**可回溯**
- [ ] 所有参数临时调整都在 `meta` 留痕，可复盘。
- [ ] 引用 / 打回 / 申辩 / 重议 / 失效均落文件，可 diff、可 grep。
