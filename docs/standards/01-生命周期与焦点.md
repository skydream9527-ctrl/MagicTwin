# 01 · 生命周期与焦点

> 规则范围：DC-06 ~ DC-10 · 上级索引：[README](./README.md)

## 一、四阶段状态机

```
        ┌──────────┐   焦点已明确且有判定标准    ┌──────────┐
 目标 → │ P1 发散  │ ────────────────────────→ │ P2 交锋  │
        │ 摊问题   │                            │ 碰观点   │
        └──────────┘                            └────┬─────┘
              ↑                                      │ 命中任一收束触发器
              │ 六类重启触发器之一（见 04）            ↓
              │                                 ┌──────────┐
              └──────────────────────────────── │ P3 收束  │ 归拢：已定事实 / 未决分歧 / 信息缺口
                                                └────┬─────┘
                                                     │ 最小可决集齐 + 共识分级达标
                                                     ↓
                                                ┌──────────┐
                                                │ P4 定案  │ 收口：结论 + 闭环 + 重启条件 + 回看时间
                                                └──────────┘
```

## 二、DC-06｜阶段单向，回退必须有触发器

P1 → P2 → P3 → P4 单向推进。从 P3/P4 回退，只认 [04 的六类重启触发器](./04-重启与重议.md)。「感觉还没聊透」「再讨论讨论」不是触发器。

## 三、DC-07｜阶段出口条件

不满足不许进下一阶段；满足了不许赖在原地。

| 阶段 | 进入条件 | 出口条件（满足即必须前进） | 该阶段禁止的事 |
|---|---|---|---|
| **P1 发散** | 已过 [DC-01 护栏](./00-总则与角色.md)，目标已给 | 列出候选问题清单，选出 1 个带判定标准的焦点 | 无焦点状态下让 Agent 自由发言 |
| **P2 交锋** | 有焦点 | 命中任一[收束触发器](./02-推进与收束判定.md) | 同轮切换焦点；无增量发言（记为 `pass`） |
| **P3 收束** | 由 P2 触发 | 产出「已定事实 / 未决分歧 / 信息缺口」三件套 | 引入新论点（新论点只能登记为下一场输入） |
| **P4 定案** | 最小可决集齐备 | [收口产出物](./03-收口与终止.md)齐备 | 为追求完美再开新轮 |

## 四、DC-08｜单焦点 + 自带判定标准

开轮前，焦点必须写成**一个**能被判真伪的问句，**并附判定标准**。写不出判定标准的问题不允许开轮——它要么该拆，要么该转成取数动作，要么该升级给决策人。

| 判定 | 示例 |
|---|---|
| 合格 | 「消费时长下滑是否主要由视频体裁贡献？判定：视频体裁贡献占降幅 ≥50% 则成立。」 |
| 合格 | 「时长与 LTV 是否为线性关系？判定：分群时长-LTV 曲线单调且相关系数 ≥0.7 则成立。」 |
| 不合格 | 「我们怎么看这次下滑？」（无判定标准，必然发散） |
| 不合格 | 「是体裁问题还是新老用户问题，另外要不要看渠道？」（多焦点，必然串线） |

**为什么这条是引擎级约束**：判定标准就是这一轮的退出条件。没有退出条件的循环，只能靠轮次上限强行截断——那是兜底，不是设计。

## 五、DC-09｜异常类议题先定位，后辩因

发现异动、报错、数据异常时，**在事实定位完成前禁止辩论原因**。定位固定四件事：

| 定位项 | 要回答 |
|---|---|
| **范围** | 影响哪些业务线 / 端 / 人群 / 时间段？是全局还是局部？ |
| **口径** | 是真异动，还是口径 / 埋点 / 统计方式变了？与官方看板是否一致？ |
| **链路** | 从上报到入仓到看板，哪一环可能出问题？ |
| **影响** | 影响谁的决策？是否影响正在跑的实验与算法特征？ |

四件事没查清就开始归因，是最典型的空转来源：各方拿着不同口径的数字辩不同的现象。

**处置动作**：定位阶段的正确动作是 `query`（查数）而不是 `speak`（发言）。主持人应直接派活取数，而不是组织讨论。

## 六、DC-10｜每 2 轮强制一次阶段小结

小结必须输出三件事，缺一不算合格小结（对齐 [DC-02 三分法](./00-总则与角色.md)）：

1. **已定事实**：这两轮被证据钉住的结论，每条带来源与口径。
2. **未决分歧**：还剩什么没定，各自属于[哪一类](./02-推进与收束判定.md)（事实 / 口径 / 价值）。
3. **可收判断**：现在能不能收？不能收的话，下一个焦点是什么。

小结是场的锚点。长讨论一旦经历上下文压缩（`server/engine/compact.js`），没有锚点就再也拼不回来。

**同一轮里第二次小结算空转（实测踩过的坑）**：合格小结不计空转，但主持人会利用这一点连续输出小结、迟迟不收口（实测连续 5 次）。所以规则是：一轮内已有合格小结后，再次小结记为空转，且下一步只能二选一——点名或收口。

**现状差异**：当前实现里 `summarize` 是可选动作，且会被计入「主持人空转」计数。按本规则，合格小结不计空转，且每 2 轮由引擎主动索要（见 [08 落地映射](./08-落地映射与验收.md)）。
