# 04 · 重启与重议

> 规则范围：DC-29 ~ DC-35 · 上级索引：[README](./README.md)
> 本份回答：**已经收束出结论之后，什么时候、以什么方式重新开始讨论。**

## 零、核心立场

收口不是「这件事定了，别再提」。判断层的结论天生允许被新证据修正（[DC-02](./00-总则与角色.md)）。所以重议是**常态**，但必须是**受控的常态**：

| 反面 | 正面 |
|---|---|
| 谁想起来就重开一遍，从零讨论 | 有触发器才重开，继承已定事实，只重议被推翻的层 |
| 收了就不管，错了也没人发现 | 每个结论带回看时间，到期主动回填判定 |
| 新结论直接覆盖旧结论 | 新老并行标差异，保留可追溯的演进链 |

一句话：

> **收口时就把「什么情况下重来、什么时候回看」写清楚，重启就不需要靠谁想起来。**

## 一、DC-29｜六类重启触发器（缺一不可开）

重开一场（或从 P3/P4 回退）只认以下触发器。**没有触发器不许重开**。

| # | 触发器 | 判定信号 | 典型场景 |
|---|---|---|---|
| **T1 新事实** | 新数据 / 新取数结果推翻已定事实 | 新 `query` 结果、`tool_result` | 补跑交叉数据后，原归因不成立 |
| **T2 口径失效** | 结论依赖的口径来源变更 | 经验包 `status: stale`、`caliber_hash` 失配 | 时长口径改算法、时间窗从自然日改 T-1 |
| **T3 验收打回** | Twin 验收发现硬伤 | `rework` | 结论没下钻到因、口径不一致 |
| **T4 决策人指令** | 目标变更 / 追加焦点 / 要求重议 | `inject` / `reply` | 决策人看到结论后要求换角度 |
| **T5 复盘发现** | 事后发现结论错误或方法有问题 | 人工发起 | 线上问题反查到当初判断错了 |
| **T6 到期回看** | 到达 `review_at`，回填判定为「部分成立」或「推翻」 | 定时扫描（见 DC-30/31） | 30 天后检查结论是否仍然成立 |

**T6 是主路径**，其余五类是事件驱动的例外。绝大多数「重新讨论」应该由到期回看触发，而不是靠谁临时想起来。

## 二、DC-30｜每个结论都带回看时间与检查问题

收口时必填两个字段，缺则收口不合格：

```yaml
review_at: 2026-08-31          # 回看日期
review_questions:              # 到期要检查的具体问题（可判定，不是「看看效果」）
  - 视频体裁贡献是否仍 ≥50%？
  - 内容分发权重调整后 CTR 是否改善？
  - 新老用户拆分数据是否已补齐？
```

**回看时间怎么定**：

| 结论类型 | 建议回看间隔 | 依据 |
|---|---|---|
| 运营级（天级、可逆） | 1~2 周 | 效果反馈快 |
| 战术级（周-月、资源分配） | 2~4 周 | 一个执行周期 |
| 战略级（季度、方向、不可逆） | 到下个周期节点 | 与 OKR 节奏对齐 |
| 依赖实验数据的结论 | 实验观测周期 + 1 周 | 例：LTV30 类结论至少 30 天 |
| 持续执行类硬规则 | 标「持续执行」，只在被违反时复议 | 例：某类评审必须请某角色 |

**检查问题必须可判定**（同 [DC-08](./01-生命周期与焦点.md) 焦点规格）：写「效果如何」不合格，写「CTR 是否较基线提升 ≥1pct」合格。

**`review_at` 必须是将来的日期（实测踩过的坑）**：模型很容易拿数据日期（如 T-2）或分析区间的结束日当回看日期，结果结论一落地就已过期、当天就被扫成「到期」。判定实现：`review_at <= 今天` 一律视为缺失，要求重写；反复缺失则按默认间隔兜底并留痕。

## 三、DC-31｜到期回填判定三态

到期时不是「重新讨论一遍」，而是先做一次低成本的**回填判定**，再决定是否值得开场。

```
到期扫描 → 搜集证据（对照 review_questions 取数 / 查记录）
        → 判定三态
           ├─ 成立      ：延长 review_at，不开场；沉淀为可复用经验
           ├─ 部分成立  ：R1 或 R2 级重议（见 DC-32）
           └─ 推翻      ：R2 或 R3 级重议，并检查是不是护栏漏了一条
```

回填记录格式（追加到原结论下方，不修改原文）：

```yaml
review_result:
  at: 2026-08-31
  verdict: 部分成立          # 成立 | 部分成立 | 推翻
  actual_vs_expected: 视频体裁贡献 42%，低于预期的 ≥50%
  gap_reason: 未剔除新用户占比上升带来的分母影响
  lesson: 结构类归因必须先做新老用户拆分再算体裁贡献
  rule_added: acceptance_checklist#rt_no_split   # 若需补规则，见 DC-28
  next: R2 级重议，继承事实层，重议归因判断
```

**判定为「推翻」时的额外动作**：检查当初的护栏与验收清单是否漏了某一条。**结论错了不只是结论的问题，通常是判定规则的问题**——这一条不补，同类错误会重复发生。

## 四、DC-32｜重议范围三档：继承什么、重验什么

重议最大的浪费是从零开始。按被推翻的层级决定重议范围。

| 档 | 触发情形 | 继承 | 重验 | 开场方式 | 预算 |
|---|---|---|---|---|---|
| **R1 局部修正** | 结论方向不变，只是量级 / 边界要调 | 事实层 + 判断层 + 行动层 | 只重算被质疑的那个数 | **不开新场**，原场补一轮或直接派活取数 | 1 轮 |
| **R2 结论重议** | 判断层可能翻转，事实层仍可信 | 事实层（标注证据等级）+ 分歧登记 | 判断层全部重议 | 新开一场，继承 `facts[]` 作为起点 | 上次的 50% |
| **R3 前提重议** | 口径变了 / 目标变了 / 前提被证伪 | 只继承「上次结论 + 为什么失效」 | 事实层也要重验 | 新开一场，视为新议题 | 全额 |

**判定口径变更一律走 R3**：口径变了意味着历史数据不可直接比较，事实层必须重验。拿旧口径的事实去支撑新口径的判断，比没有结论更危险。

**R2/R3 开场时的必备注入**（避免重复上次的弯路）：

1. 上一版结论 + 回填判定结果。
2. 已定事实（含证据等级），明确哪些仍可信、哪些需重验。
3. 上次的分歧登记表（哪些分歧当时没解决、缺什么信息）。
4. 上次踩过的坑（本议题相关的 `rt_*` / 踩坑规则）。
5. **本次重议的判定标准**（同 DC-08，必须自带退出条件）。

## 五、DC-33｜不覆盖旧结论：新老并行，标注差异

重议产出新结论时，**不允许直接覆盖或删除旧结论**。

| 要求 | 说明 |
|---|---|
| 保留旧结论 | 旧结论标 `superseded_by: <新结论 id>`，原文不改 |
| 新结论标来源 | 新结论标 `supersedes: <旧结论 id>` + **差异说明**（差多少、为什么差） |
| 量化差异 | 「新老差异 X%」必须给数，不许只写「口径调整后有变化」 |
| 并行期 | 涉及口径 / 基线切换的结论，新老口径并行观察，达标后再切；不硬切 |

**为什么**：这是从埋点与口径切换里换来的经验。硬切会让指标出现无法解释的跳变，历史对比全部失效。讨论结论同理——**没有差异说明的覆盖，等于让所有引用过旧结论的下游产物静默失效**。

## 六、DC-34｜同一议题的重议预算递减

防止同一件事被无限重议消耗精力。

| 次数 | 预算 | 附加要求 |
|---|---|---|
| 第 1 次重议 | 上次的 50% 轮次 | 必须带触发器 |
| 第 2 次重议 | 上次的 50%（即初始 25%） | 必须说明「上次重议为什么没定住」 |
| 第 3 次及以后 | 不允许自动重议 | 必须由决策人显式批准，或转为「长期观察项」定期回填、不开场 |

**第 3 次重议是强信号**：说明这个议题要么信息永远不足（该转长期观察 + 定期回填），要么本质是价值分歧（该由决策人直接拍板），要么焦点一直没定对（该拆题）。继续重议只是把同一个坑挖深。

## 七、DC-35｜暂缓 / 降优 / 不做，必须带重启条件

任何「当前先不做」的结论，必须写清什么条件下重启。缺重启条件的暂缓，等于把事情悄悄丢掉。

重启条件三要素：

| 要素 | 说明 | 反例 |
|---|---|---|
| **触发条件** | 具体、可观测的事件或阈值 | 「等有时间」「等成熟了」 |
| **判定人** | 谁来判断条件是否满足 | 无人负责 |
| **兜底回看时间** | 条件一直不触发时，什么时候强制复评 | 没有兜底，永远不回看 |

标准表述（可直接作为交付话术）：

> 这件事当前先降到 P1。资源先保 [P0 事项]；本轮只做 [范围]，[范围外的事] 暂缓。等 [触发条件] 满足后由 [判定人] 重新评估；若未触发，[日期] 强制复评。

## 八、完整重启时序

```
收口（P4）
  ├─ 写 restart_condition（DC-35）
  ├─ 写 review_at + review_questions（DC-30）
  └─ 写 next_steps（责任人/期限/完成标准）
        │
        ├── T1~T5 事件到达 ────────────┐
        │                              │
        └── 到达 review_at             │
              ↓                        │
        回填判定（DC-31）               │
          ├─ 成立     → 延长回看，沉淀经验，不开场
          ├─ 部分成立 → ┐              │
          └─ 推翻     → ┤              │
                        ↓              ↓
                  定重议档位（DC-32：R1 / R2 / R3）
                        ↓
                  R1：原场补一轮 ─────────→ 直接产出修正
                  R2/R3：新开一场（注入五件事）→ 回到 P1/P2
                        ↓
                  新结论标 supersedes + 差异说明（DC-33）
                        ↓
                  重议预算递减（DC-34）
```
