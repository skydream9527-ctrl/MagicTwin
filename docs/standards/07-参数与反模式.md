## 二、反模式清单（命中即违规）

| # | 反模式 | 为什么有害 | 对应规则 |
|---|---|---|---|
| AP-01 | **互相吹捧**：「同意 X 的精彩分析」 | 零增量，制造虚假共识 | DC-13 |
| AP-02 | **复述式发言**：换词重说已有观点 | 消耗轮次与 token | DC-14 |
| AP-03 | **无穷追问**：不断「能否再细化」 | 追问不带判定标准，永不收敛 | DC-08 |
| AP-04 | **以打回代替决策**：反复打回却不说过关线 | 把决策成本转嫁给执行方 | DC-37 |
| AP-05 | **共识做成投票**：多数票盖过数据 / 红线 | 结论与事实脱钩 | DC-25 |
| AP-06 | **用讨论回避动作**：能查数却继续辩 | 事实分歧只能被数据裁决 | DC-16 |
| AP-07 | **Twin 下场辩论** | 裁判兼选手，压掉专家判断 | DC-39 |
| AP-08 | **终止代替收口**：有部分结论却无产出结束 | 已投入的工作全部作废 | DC-21 |
| AP-09 | **无触发重开**：「再讨论讨论」 | 场无终局 | DC-29 |
| AP-10 | **抹平分歧**：为了结论好看删掉反对意见 | 隐藏风险，事后返工 | DC-24 |
| AP-11 | **超时默认同意高风险项** | 治理漏洞制度化 | DC-49 |
| AP-12 | **多焦点同轮** | 串线，无法判定任何一个 | DC-08 |
| AP-13 | **虚构共识**：把「无人反对」写成「已对齐」 | 后续按不存在的共识推进，返工代价高 | DC-03 |
| AP-14 | **静默覆盖旧结论**：重议后直接改写，不标差异 | 引用旧结论的下游产物全部静默失效 | DC-33 |
| AP-15 | **未定位就辩因**：异动刚发现就争原因 | 各方拿不同口径的数辩不同的现象 | DC-09 |
| AP-16 | **一次抛一堆确认项** | 把 AI 产出速度转换成对人的打扰频率 | DC-20 |

## 三、收口前自检清单

主持人收口前逐条过；不输出给用户，但要落在 `round_check` 事件里。

**结论层**
- [ ] 是否有一句话结论（方向 + 幅度），不是只堆数据？
- [ ] 事实、判断、行动是否分开写？
- [ ] 每条事实是否带来源、口径、证据等级？C/D 级是否已标「推断」？
- [ ] 每条判断是否能追溯到具体事实？
- [ ] 结论是否写明口径边界与异常处理？

**共识层**
- [ ] 写进 `consensus` 的每一条，是否都有明确确认记录？（无则改「当前建议 + 待确认」）
- [ ] 未决分歧是否结构化登记（含类型、为何未解决、解决所需、影响）？
- [ ] 是否存在「多数意见与数据 / 红线冲突」而未指出？

**行动层**
- [ ] 每条下一步是否有责任人、期限、完成标准？未确认的是否用 `[待确认]`？
- [ ] 是否替谁承诺了未确认的资源、期限或结果？
- [ ] 高风险项是否已升级而非代答？升级是否只问了一个最小问题？

**重启层**
- [ ] 是否写了重启条件（触发条件 + 判定人 + 兜底回看时间）？
- [ ] 是否写了 `review_at` 与可判定的 `review_questions`？
- [ ] 若本次是重议，是否标了 `supersedes` 与差异说明（含量化差异）？

**机制层**
- [ ] 本场暴露的机制缺口是否已登记待补（24 小时内）？
- [ ] 参数是否有临时调整？是否已在 `meta` 留痕？
