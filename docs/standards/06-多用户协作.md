# 06 · 多用户协作

> 规则范围：DC-44 ~ DC-50 · 上级索引：[README](./README.md)
> 一个工作空间里同时有多个用户参与讨论时，最大的新风险不是技术性的，而是**权责错位**：谁说的算？Agent 该听谁的？

## 一、DC-44｜发言权与决策权分离

所有参与用户都有发言权（`inject`），但**每个议题只有一个决策人**。

| 项 | 规则 |
|---|---|
| 默认决策人 | 任务创建者（`meta.uid`） |
| 移交 | 可显式移交，必须留痕（谁移交给谁、何时） |
| 无决策人 | **不许进入 P4 定案**。可以讨论、可以收束到 P3，但不能定案 |
| 多议题 | 一场里若拆出多个议题，各议题可以有不同决策人，但每个议题仍只有一个 |

## 二、DC-45｜Twin 不裁决人与人之间的分歧

两个用户意见冲突时，Twin 的唯一合法动作是：**呈现双方立场 + 给出带取舍的建议 + 请决策人拍板**。

| 场景 | 错误做法 | 正确做法 |
|---|---|---|
| A 说该做，B 说不该做 | 「综合看 A 更有道理」 | 「A 的理由是 X，B 的理由是 Y；差异点在 Z。建议按 A，因为 [依据]。请 [决策人] 确认」 |
| A、B 对优先级有分歧 | 自行排序 | 按 [DC-16](./02-推进与收束判定.md) 归为 `value` 分歧 → 升级 |

Agent 在人际分歧中站边，会立刻摧毁它作为中立工具的价值——**下一次它说的任何话都会被当成某一方的立场**。

## 三、DC-46｜每个 Twin 只代表本人

| 约束 | 说明 |
|---|---|
| 不跨人代答 | 用户 A 的 Twin 不得替用户 B 代答确认项 |
| 不跨人读私有空间 | 不得读 B 的画像、偏好、私有记忆（隔离矩阵） |
| 跨用户确认项一律升级 | 涉及 B 的决定，升级给 B 本人，不由 A 的 Twin 推断 |
| 审计可见 ≠ 内容可读 | 管理员因运维可见元数据与审计，但不读私有内容 |

## 四、DC-47｜讨论共享，记忆隔离

**公开讨论不等于公共记忆。**

| 维度 | 规则 |
|---|---|
| 讨论记录（`transcript`） | 全场共享，所有参与者可回看 |
| 情景记忆沉淀 | 按 `uid` 分区（`agents/{aid}/memory/by-user/{uid}/`） |
| 进团队记忆 | 必须走候选 → 审批 → 晋升，不由讨论自动完成 |
| 引用别人的经验包 | 先按访问边界过滤，再排序；无权访问的不进候选集 |

**为什么必须分开**：如果讨论内容自动进团队记忆，一次多人讨论就会把某个人的偏好、口径、判断固化成所有人未来的默认——这是最难回滚的一类污染。

## 五、DC-48｜并发插话按边界合并处理

| 情形 | 处理 |
|---|---|
| 多用户同时插话 | 在同一个发言 / 轮次边界一次性注入给主持人，由主持人统一裁决焦点 |
| 顺序 | 按到达顺序串行处理，不交叉 |
| 冲突指令（A 要收口、B 要继续） | 按 DC-44 交决策人；决策人未响应时按 DC-49 处理 |
| 非决策人的指令 | 标为「建议」，不直接改变焦点、不触发收口 |

不做合并的后果：焦点被反复抢占，每轮都在切题，[DC-08 单焦点](./01-生命周期与焦点.md) 直接失效。

## 六、DC-49｜静默即弃权，但按风险分级

待确认项超时（默认 1 个工作日，或场内 3 轮）无决策人响应：

| 风险等级 | 超时处置 |
|---|---|
| **低风险** | 按代答默认值继续，**在交付物中标注「超时默认，未经确认」** |
| **中风险** | 继续但降级：给保守方案 + 显式标注假设 + 记入 `decision_log` |
| **高风险** | **挂起，不推进。** 绝不允许「超时即视为同意」 |

**高风险绝不默认同意**——把治理漏洞制度化，比慢一天严重得多。高风险的判定依据是风险矩阵与护栏（不可逆 / 对外承诺 / 影响主线 / 超 3 人天）。

## 七、DC-50｜群聊语境纪律

多人在场时，Twin 的发言等同于群聊发言，适用更严的公开性约束：

| 约束 | 说明 |
|---|---|
| 只同步可公开的事实与动作 | 不把某个用户的私聊结论、私有偏好、敏感判断扩散到全场 |
| 点人要准 | 需要谁跟进就明确指向谁，不用「大家跟进一下」 |
| 不公开施压 | 催办说事实与期限，不做评价性表述 |
| 敏感分歧转私 | 涉及个人评价、绩效、人事的分歧不在多人场展开，转给决策人私下处理 |
