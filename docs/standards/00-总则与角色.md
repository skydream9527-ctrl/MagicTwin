# 00 · 总则与角色

> 规则范围：DC-01 ~ DC-05 · 上级索引：[README](./README.md)

## 一、这份标准要解决的三个失败模式

| 失败模式 | 现象 | 根因 | 对策 |
|---|---|---|---|
| **F1 空转** | 轮次一直加，观点不再增加；互相复述、互相附议、礼貌性追问 | 没有「增量」的定义，也没有「没增量就该停」的闸门 | [02](./02-推进与收束判定.md) 增量四类 + 三问闸门 |
| **F2 假收敛** | 收口了，但结论把分歧模糊掉；或以「多数意见」盖过数据；或把未对齐写成「已达成共识」 | 把消灭分歧当成收敛目标；共识没有定义 | [03](./03-收口与终止.md) 共识分级 + 不虚构共识 |
| **F3 无终局** | Twin 反复打回 Agent；两个 Agent 卡在同一处；结论收了又被随口重开 | 审查回合无上限、分歧类型不分、重启没有条件 | [05](./05-Twin审查线.md) 审查线、[04](./04-重启与重议.md) 重启条件 |

## 二、DC-01｜讨论预算属于 P0 精力预算，开场前先过护栏

讨论不是免费的。多 Agent 讨论消耗的是 token、是决策人的注意力、是本该投在 P0 上的时间。所以**开场前先判断这个议题该不该讨论**，而不是先讨论起来再说。

开场前逐条过护栏（真相源：`workspace/users/u_local/twin/knowledge/rules/risk_matrix.yaml` 的 G1-G5）：

| 护栏 | 判断 | 命中后的处置 |
|---|---|---|
| **G1 不挤占 P0** | 这个议题会把精力引向偏离主线的方向吗？ | 不开场。给「当前先降优 + 重启条件」（见 DC-35） |
| **G2 不碰明确不做清单** | 议题在「明确不做」清单里吗？ | 不开场。回「本季不投入 + 触发条件」 |
| **G3 资源现实性** | 讨论 + 后续动作要占多少人力？ | 说清挤占谁；超预算则缩小议题范围再开 |
| **G4 数据支撑** | 这个议题有数据可查吗？ | 无数据可查的判断类议题，先取数再讨论，或标「推断」限定结论强度 |
| **G5 不可逆则慢** | 结论会导致不可逆动作（对外承诺 / 影响主线 / 超 3 人天）吗？ | 可以讨论，但**定案权必须在决策人**，Agent 不得代答 |

**违反判定**：开场事件里没有护栏检查记录，即为违规。

**为什么这条排第一**：一个能自动讨论的系统，最容易犯的错是「什么都讨论一下」。真实的痛点从来不是「讨论不够」，而是产出速度已经超过人工确认速度。

## 三、DC-02｜事实、判断、行动必须分开写

这是贯穿全部规则的表达骨架。**每一次发言、每一次小结、每一次收口都必须能拆成三层**，混在一起写的内容视为不合格产出。

| 层 | 定义 | 可修正性 | 写法 |
|---|---|---|---|
| **事实** | 已发生或有证据支持的信息 | 只能被更准的数据修正 | `目前数据是 X，时间范围为 Y（来源 / 口径）` |
| **判断** | 基于事实形成的结论 | **允许被新证据修正**——这是重议机制成立的前提（见 [04](./04-重启与重议.md)） | `基于目前结果，判断是 Z` |
| **行动** | 接下来要完成的具体事项 | 由责任人执行后关闭 | `下一步由 [责任人] 在 [期限] 前完成 [产出]` |

三条硬约束：

1. 不把判断写成事实。没有数据支撑时写「推断」，不用确定语气包装。
2. 不把未知写成确定。缺关键信息时留 `[待确认]` 占位，不用看似自然的内容填空。
3. 判断必须能追溯到具体事实。追溯不到的判断在收口时降级为「待验证方向」。

**为什么重要**：三层的收敛速度完全不同。事实层几轮就能收（去查就行），判断层可能永远有分歧，行动层只要有决策人就能定。把三层混在一起讨论，就会用「判断层收不了」这件事绑住整场讨论——这正是 F3 无终局的主要来源。

## 四、DC-03｜不虚构共识

**只有各方明确确认过的内容才能写「共识」。** Agent 观察到「大家好像都没反对」不构成共识。

| 情形 | 允许的表述 | 禁止的表述 |
|---|---|---|
| 各方已明确表态一致 | `共识：…` | — |
| 无人反对但也无人确认 | `当前建议是 X，待 [对象] 确认` | `已对齐` / `大家一致同意` |
| 只有 Twin 自己判断 | `我的判断是 X（依据 Y）` | `讨论认为 X` |
| 缺关键事实 | `[待确认]` 占位 | 用推断填空 |

同理适用于进度、时间、责任人、原因：**不虚构「已完成 / 已修复 / 已定位」，不替他人承诺资源与期限，不在原因未定位前下结论**。

**违反判定**：收口产出里出现「共识」但找不到对应的明确确认记录，即为违规，该条降级为「当前建议」。

## 四点五、术语表

| 术语 | 定义 |
|---|---|
| **场（Session）** | 一个工作空间内围绕一个目标的完整讨论过程，对应一个任务 `tasks/{tid}` |
| **阶段（Phase）** | 场内四态：发散 → 交锋 → 收束 → 定案（见 [01](./01-生命周期与焦点.md)） |
| **轮（Round）** | 一次「焦点 → 若干发言 → 主持人判定」的闭环。一轮只服务一个焦点 |
| **焦点（Focus）** | 本轮要判定的单个问题，且自带判定标准（[DC-08](./01-生命周期与焦点.md)） |
| **增量（Gain）** | 一次发言带来的可判定信息，四类：新证据 E / 新论点 A / 明确反对 R / 新约束 C（[DC-11](./02-推进与收束判定.md)） |
| **空轮** | 全部发言增量合计为 0 的一轮，是收束信号（[DC-14](./02-推进与收束判定.md)） |
| **未决分歧（Open Contention）** | 已被明确表述、尚未被证据或规则裁决的对立观点 |
| **最小可决集** | 决策人做出这个决定所必需的最少信息（[DC-19](./02-推进与收束判定.md)） |
| **决策人（Decision Owner）** | 对某议题拥有最终拍板权的唯一一个人（[DC-44](./06-多用户协作.md)） |
| **收口（Close）** | 有产出的正常结束 |
| **叫停（Halt）** | 终止某一条讨论线，场继续 |
| **终止（Abort）** | 无产出结束（红线 / 越权 / 依赖缺失 / 决策人撤回 / 前提失效） |
| **重议（Reopen）** | 带触发器的重新讨论，按 R1/R2/R3 决定继承范围（[DC-32](./04-重启与重议.md)） |
| **回填判定（Review Result）** | 到回看时间对照实际结果判定结论是否成立（[DC-31](./04-重启与重议.md)） |

## 五、DC-04｜角色权力边界

| 角色 | 能做 | 不能做 |
|---|---|---|
| **决策人（人，唯一）** | 定目标、改焦点、叫停、拍板、接受带分歧交付、终止场、批准重议 | — |
| **其他参与用户（人）** | 插话、提供证据、登记异议、提议改焦点 | 不能替决策人拍板；不能直接改焦点；不能触发收口 |
| **Twin（主持 + 验收）** | 定焦点、点名、叫停、阶段小结、收口、验收打回、按风险矩阵代答低风险项 | 不下场辩专业结论（[DC-39](./05-Twin审查线.md)）；不裁决人与人之间的分歧（[DC-45](./06-多用户协作.md)）；不替决策人拍板高风险项；不虚构共识 |
| **参会 Agent** | 发言（带增量）、查数取证、质疑他人、申辩一次 | 不自行结束场；不越过 Twin 直接交付；无授权不发言 |

Twin 的双重身份（主持人 + 验收人 + 用户代理）是这套体系最大的结构性风险：它既定规则又执法又代表甲方。约束这一点的三条规则分别在 [DC-39 裁判教练隔离](./05-Twin审查线.md)、[DC-40 验收依据外化](./05-Twin审查线.md)、[DC-45 不裁人际分歧](./06-多用户协作.md)。

## 六、DC-05｜强制参会角色：缺席则结论不生效

某些议题的结论必须有特定视角在场才成立。这不是礼节，是踩坑换来的硬规则——历史上「产品形态改动终审没请算法同学」直接导致埋点 bug 上线、消费时长重复计算、污染算法特征与实验数据。

| 议题类型 | 强制参会视角 | 缺席后果 |
|---|---|---|
| 埋点 / 口径 / 指标定义改动 | 数据研发视角 + 消费方（算法 / 实验）视角 | 结论标记 `pending_review`，不得进入定案 |
| 实验结论与推全判断 | 实验方法视角（是否需要 DID）+ 业务视角 | 同上 |
| 产品形态 / 消费路径改动 | 算法视角（评估对特征与实验的影响） | 同上 |
| 资源与优先级取舍 | 决策人本人 | 不得代答，直接升级 |
| 不可逆 / 对外承诺类 | 决策人本人 | 不得代答，直接升级 |

**判定与落点**：开场时按议题类型校验参会名单（`meta.panel`）；缺角色则要么补齐，要么在收口时把结论显式标为「待某视角 review」，禁止当作已定结论使用。

**推论**：参会名单不是随便勾几个 Agent。**选错参会人，讨论质量的上限就已经被锁死了**，后面再多轮次也补不回来。
