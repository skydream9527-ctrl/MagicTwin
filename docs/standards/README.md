# 讨论标准 · 目录索引

> 定位：多用户 + 多 Agent 在同一工作空间讨论时，**该不该继续、何时收、怎么收、收完怎么重来**的规则集。
> 版本：v2.0 · 更新：2026-07-28（v1.0 为 `docs/STANDARD-多方讨论收敛标准.md`，已并入本目录）
> 规则编号 `DC-01` ~ `DC-50`，可在代码注释、prompt、评审中直接引用。
> 适用：圆桌讨论（`mode=roundtable`）、常规编排多方往返（`assign`/`report`/`ask`）、**Twin 对其他 Agent 交付物的检查与验收**。

## 一句话总纲

> **讨论的目的不是达成一致，而是把一个问题推进到「可以被决定」的状态。可以被决定之后，多讨论一轮就是纯成本；而任何结论都带回看时间，到期该重议就重议。**

## 一页速查卡

**开场前过护栏（DC-01）**
议题命中「明确不做」清单、或会挤占 P0 → 不开讨论，直接给「降优 + 重启条件」。讨论本身消耗 P0 精力。

**开轮前问三件事（DC-08）**
焦点是一个吗？有判定标准吗？上一轮有增量吗？任一为否，不开轮。

**每轮末过三问（DC-15，主闸）**
Q1 还有未决分歧？ Q2 上轮有增量？ Q3 预算够再判一次？任一为否就前进——收束 / 转动作 / 升级 / 收口。

**看到分歧先分类（DC-16）**
事实分歧 → 查数；口径分歧 → 查规则；价值分歧 → 问决策人。**都不是「再辩一轮」。**

**异常类议题先定位（DC-09）**
先定范围、口径、链路、影响，再谈原因。未定位前禁止辩因。

**收口门槛（DC-23）**
事实共识（C1）+ 行动共识（C3）即可定案。判断分歧登记，不消灭。未明确对齐的一律不写「共识」，写「当前建议 + [待确认]」。

**收口必带四件（DC-22）**
结论（事实/判断/行动分开写）· 最小闭环（责任人 + 期限 + 完成标准）· 重启条件 · 回看时间。

**审查交付物（DC-36 / DC-37）**
最多打回 2 次；每次引 `pc_*`/`rt_*` 条目、说清补什么和过关线；第 3 次改为「带缺陷交付 / 升级 / 换人换法」。

**多用户（DC-44 / DC-45）**
人人可发言，一个议题一个决策人；Twin 呈现分歧、给建议，不裁决人与人。

**三种结束（DC-21）**
`close` 有产出 / `halt` 停一条线 / `abort` 无产出。有部分结论就必须收口，不许终止。

**重启（DC-29 / DC-32）**
只认六类触发器（新事实 / 口径失效 / 验收打回 / 决策人指令 / 复盘发现 / **到期回看**）。重议继承已定事实，只重议被推翻的层；不覆盖旧结论，新老并行标差异。

这套标准的主闸已经在代码里跑起来了，不只是文档。逐条状态见 [08 落地映射与验收](./08-落地映射与验收.md)。

## 更新机制

1. 新规则先在真实任务里被违反过至少一次，再写进标准；不预设未发生的问题。
2. 每条规则必须可判定：写不出「怎么算违反」的规则不收录。
3. 参数调整（轮次、打回额度、超时）只改 07 的参数表，不改规则正文。
4. 规则被证伪或长期不触发 → 标注废弃并说明原因，不静默删除。
5. 讨论中暴露的机制缺口，24 小时内补进对应清单（验收清单 / 护栏 / 踩坑表），见 DC-28。
