# 标准 · 多 Agent 讨论的推进、收束与终止

> 文档类型：标准与规则规范（Standard）
> 版本：v1.0
> 适用范围：**一个工作空间内**，用户 + 多个 Agent 同台的讨论型协作——包括圆桌讨论（`mode=roundtable`）、常规编排中的多方往返（`assign`/`report`/`ask`），**尤其是 Twin 对其他 Agent 交付物的检查与验收**。
> 定位：机制设计回答"**能怎么讨论**"，本标准回答"**该不该继续讨论、何时收、怎么收**"。规则均编号（`DC-xx`）以便在代码注释、prompt、评审中引用。

---

## 一、这份标准要解决的三个失败模式

多方讨论天然会坏在三个地方，本标准的每一条规则都对应其中之一：

| 失败模式 | 现象 | 根因 | 本标准的对策 |
|---|---|---|---|
| **F1 空转** | 轮次一直加，观点不再增加；互相复述、互相附议、礼貌性追问 | 没有"增量"的定义，也没有"没增量就该停"的闸门 | §4 增量四类 + 三问续议闸门 |
| **F2 假收敛** | 收口了，但结论是把分歧模糊掉的和事佬版本；或以"多数意见"盖过数据 | 把"消灭分歧"当成收敛目标 | §7 共识分级 + 带分歧交付 |
| **F3 无终局** | Twin 反复打回 Agent，或两个 Agent 卡在同一处；讨论既不产出也不终止 | 审查回合无上限、分歧类型不分、决策人不唯一 | §6 分歧三分法、§9 审查线、§10 决策人唯一 |

一句话总纲：

> **讨论的目的不是达成一致，而是把一个问题推进到"可以被决定"的状态。一旦可以被决定，多讨论一轮就是纯成本。**

## 二、术语与角色

| 术语 | 定义 |
|---|---|
| **场（Session）** | 一个工作空间内围绕一个目标的完整讨论过程，对应一个任务 `tasks/{tid}`。 |
| **阶段（Phase）** | 场内的四个状态：发散 → 交锋 → 收束 → 定案（§3）。 |
| **轮（Round）** | 一次"焦点 → 若干发言 → 主持人判定"的闭环。一轮只服务**一个焦点**（`DC-05`）。 |
| **焦点（Focus）** | 本轮要判定的**单个**问题，且**自带判定标准**（`DC-05`）。 |
| **增量（Gain）** | 一次发言带来的可判定信息，四类：新证据 E / 新论点 A / 明确反对 R / 新约束 C（§4.1）。 |
| **未决分歧（Open Contention）** | 已被明确表述、且尚未被证据或规则裁决的对立观点。 |
| **决策人（Decision Owner）** | 对某议题拥有最终拍板权的**唯一一个人**（§10）。 |
| **收口（Close）** | 有产出的正常结束（`close` / `deliver`）。 |
| **叫停（Halt）** | 终止**某一条讨论线**，场继续（`halt`）。 |
| **终止（Abort）** | 无产出结束（红线、越权、依赖缺失、决策人撤回）。 |

角色权力边界：

| 角色 | 能做 | 不能做 |
|---|---|---|
| **决策人（用户）** | 定目标、改焦点、叫停、拍板、接受带分歧交付、终止场 | — |
| **Twin（主持 + 验收）** | 定焦点、点名、叫停、阶段小结、收口、验收打回、按风险矩阵代答 | **不下场辩专业结论**（`DC-25`）；不替决策人拍板高风险项 |
| **参会 Agent** | 发言（带增量）、查数取证、质疑他人、申辩一次 | 不自行结束场；不越过 Twin 直接对用户交付；无授权不发言 |

## 三、四阶段状态机

```
        ┌──────────┐   焦点已明确且有判定标准    ┌──────────┐
 目标 → │ P1 发散  │ ────────────────────────→ │ P2 交锋  │
        │ 摊问题   │                            │ 碰观点   │
        └──────────┘                            └────┬─────┘
              ↑                                      │ 命中任一收束触发器（§6）
              │ 出现全新事实/口径变更/打回             ↓
              │                                 ┌──────────┐
              └──────────────────────────────── │ P3 收束  │ 归拢：已定事实 / 未决分歧 / 缺口
                                                └────┬─────┘
                                                     │ 达到最小可决集 + 共识分级达标（§7）
                                                     ↓
                                                ┌──────────┐
                                                │ P4 定案  │ 收口交付：结论 + 分歧登记 + 决策记录
                                                └──────────┘
```

**DC-01｜阶段单向，回退需要新触发器。** P1→P2→P3→P4 单向推进。从 P3/P4 回退到 P1/P2 **必须**有新触发器（§5 `DC-10` 的五类触发器），不接受"感觉还没聊透"这类无触发回退。

**DC-02｜每个阶段有硬性出口条件**，不满足不许进下一阶段，满足了不许赖在原地：

| 阶段 | 进入条件 | 出口条件（满足即必须前进） | 该阶段禁止的事 |
|---|---|---|---|
| **P1 发散** | 场建立，目标已给 | 已列出候选问题清单，并选出 1 个带判定标准的焦点 | 禁止在无焦点状态下让 Agent 自由发言 |
| **P2 交锋** | 有焦点 | 命中 §6 任一收束触发器 | 禁止同轮切换焦点；禁止无增量发言（记为 `pass`） |
| **P3 收束** | 由 P2 触发 | 已产出「已定事实 / 未决分歧 / 信息缺口」三件套 | 禁止引入新论点（新论点只能登记为下一场输入） |
| **P4 定案** | 最小可决集齐备（§6.3） | 收口产出物齐备（§8.1） | 禁止为追求完美再开新轮 |

## 四、核心闸门：三问续议判定

### 4.1 增量四类（Gain）与空轮

每次发言必须能被归入至少一类增量，否则视为无效发言：

| 类型 | 含义 | 判据 |
|---|---|---|
| **E 新证据** | 带来此前场内没有的事实 | 有数据 / 有查询结果 / 有可核验的来源；口头断言不算 |
| **A 新论点** | 提出未被讨论过的机制、维度或解释 | 与已有发言不同构，不是换词复述 |
| **R 明确反对** | 指名反对某个具体观点并给出理由 | 有反对对象 + 有理由；"我觉得还要再看看"不算 |
| **C 新约束** | 引入口径、红线、资源、时间等硬约束 | 能改变可选方案集合 |

**DC-03｜纯附议不计增量，但计共识票。** 无新证据的 `support` 记 Gain=0，但在共识分级（§7）里计为一票赞同——它对收敛有用，对推进无用。

**DC-04｜空轮定义。** 一轮结束时若全部发言 Gain 总和为 0（含全员 `pass`、纯附议、纯复述），该轮记为**空轮**。空轮是收束触发器的输入信号，不是继续讨论的理由。

### 4.2 焦点必须自带判定标准

**DC-05｜单焦点 + 可判定。** 开轮前，焦点必须写成一个**能被判真伪的问句 + 判定标准**。写不出判定标准的问题，不允许开轮——它要么该拆，要么该转成取数动作，要么该升级给决策人。

- ✅ 合格："消费时长下滑是否主要由视频体裁贡献？判定：视频体裁贡献占降幅 ≥50% 则成立。"
- ❌ 不合格："我们怎么看这次下滑？"（无判定标准，必然发散）
- ❌ 不合格："下滑是体裁问题还是新老用户问题，另外要不要看渠道？"（多焦点，必然串线）

### 4.3 三问续议闸门（本标准的主闸）

**DC-06｜每轮结束时，主持人必须过一遍三问；三问全为"是"才继续，任一为"否"立即前进。**

```
Q1 还有未决分歧吗？        （open contention 非空）
Q2 上一轮产生了增量吗？    （lastRoundGain > 0）
Q3 预算还够再判一次吗？    （轮次 / 步数 / token / 时长 均未触顶）
```

判定伪代码（可直接落到 `runRoundtable` 的主持人轮末）：

```js
// 返回下一步动作：CONTINUE | CONVERGE | ESCALATE | ACT | CLOSE_FORCED | ABORT
function decideNext(s) {
  if (s.redlineHit)                      return "ABORT";        // §8.3 红线：立即无产出终止
  if (s.openContention.length === 0)     return "CONVERGE";     // Q1 否：没分歧可议
  if (s.budgetUsedRatio >= 1.0 ||
      s.round >= MAX_ROUNDS)             return "CLOSE_FORCED"; // Q3 否：预算耗尽，强制收口
  if (s.emptyRounds >= STALL_LIMIT)      return "CONVERGE";     // Q2 否：连续空轮 = 僵局
  const top = s.openContention[0];
  if (top.kind === "fact")               return "ACT";          // §6.1 事实分歧 → 转取数，不辩
  if (top.kind === "caliber")            return "ACT";          // §6.1 口径分歧 → 查真相源，不辩
  if (top.kind === "value")              return "ESCALATE";     // §6.1 价值分歧 → 升级决策人，不辩
  if (s.budgetUsedRatio >= 0.8)          return "CONVERGE";     // §6.1 预算水位：留出收口余量
  return "CONTINUE";
}
```

**注意 `ACT` 与 `ESCALATE` 的地位**：它们不是"继续讨论"，而是"离开讨论去解决"。本标准明确反对用讨论替代动作（§12 反模式 AP-6）。

### 4.4 强制节律：每两轮一次阶段小结

**DC-07｜每 2 轮必须做一次阶段小结**（`summarize`），且小结必须输出三件事，缺一不算合格小结：

1. **已定事实**：这两轮里被证据钉住的结论（每条带来源）。
2. **未决分歧**：还剩什么没定，各自属于哪一类（§6.1）。
3. **可收判断**：现在能不能收？不能收的话，**下一个焦点是什么**。

小结是场的"锚点"。没有锚点的长讨论必然漂移，并且一旦上下文被压缩就再也拼不回来。

## 五、什么时候开新一轮

先区分三个容易混为一谈的动作——选错就是发散的开始：

| 动作 | 适用情形 | 代价 | 协议动作 |
|---|---|---|---|
| **换焦点（同场内）** | 当前焦点已判定 or 已确认判不了，但目标尚未达成 | 低 | `halt` + `redirect`，或 `grant` 带新 `focus` |
| **开新一轮（同焦点再议）** | 焦点未判定，且**有新增量刚刚到达**（新数据/新约束） | 中 | `grant` 下一位发言 |
| **拆场（新建讨论）** | 出现 2 个以上**相互独立**的未决问题 | 高，但省总时间 | 新任务，或转 `fanout` 并行 |

**DC-08｜同焦点再议的唯一许可条件：** 上一轮 Gain > 0 **且** 该增量直接作用于当前焦点的判定标准。为"让大家都说一句"而开的轮次，一律不许开。

**DC-09｜拆场判据：** 若两个未决问题**互不为前提**（解决 A 不需要 B 的答案），必须拆——放在同一场里必然互相污染上下文、拉长轮次。若 B 依赖 A，则严格先 A 后 B，不许并议。

**DC-10｜重开一场（P3/P4 回退）需要新触发器**，只认以下五类：

| 触发器 | 说明 |
|---|---|
| T1 新事实 | 新数据 / 新口径 / 外部事实变化推翻已定事实 |
| T2 口径失效 | 依赖的口径来源变更 |
| T3 验收打回 | Twin 验收发现硬伤 |
| T4 决策人新指令 | 目标变更 / 追加焦点 / 要求重议 |
| T5 复盘发现 | 事后发现结论错误 |

**没有触发器就不许重开**。"再讨论讨论"不是触发器。

## 六、什么时候收束：分歧三分法与最小可决集

### 6.1 分歧三分法（本标准最锋利的一条）

**DC-11｜每一条未决分歧必须先归类，再决定怎么处置。分类错了，后面全错。**

| 分歧类型 | 特征 | **正确处置** | 错误处置（常见） |
|---|---|---|---|
| **事实分歧（fact）** | 双方对"数据是多少 / 现象是否存在"看法不同 | **停止辩论，去查数**（`query`）。数据回来就自动裁决 | 各自援引印象反复辩 |
| **口径分歧（caliber）** | 双方结论不同源于口径不同（时间窗 / 去重 / 分母） | **停止辩论，查口径真相源**。规则说了算 | 争"谁的口径更合理" |
| **价值分歧（value）** | 分歧源于取舍偏好（做不做、优先级、能否接受风险） | **停止辩论，升级决策人**（`escalate`）。这类分歧**不可能被数据消灭** | Agent 之间辩优先级，或 Twin 越权拍板 |

推论（记住这一句就够）：

> **能被数据裁决的分歧，多辩一轮不如查一次；不能被数据裁决的分歧，辩一百轮也不会收敛。所以"继续辩论"的适用面比直觉窄得多——它只适合"论点还没被摊出来"的阶段。**

### 6.2 五个收束触发器

**DC-12｜命中任一即进入 P3 收束**，不需要凑满：

| # | 触发器 | 判定 |
|---|---|---|
| CT1 | **可决** | 已达到最小可决集（§6.3）——决策所需的最少信息已齐 |
| CT2 | **僵局** | 连续 `STALL_LIMIT`（默认 2）轮空轮（`DC-04`） |
| CT3 | **场外** | 剩余分歧全部为 `value` 类，或需要场内拿不到的外部信息 |
| CT4 | **预算** | 轮次 / 步数 / token / 时长任一到 80% 水位 |
| CT5 | **叫停** | 决策人要求收口，或主持人判定继续的边际价值低于成本 |

**DC-13｜倾向早收。** 判定模糊时选择收束。理由：收束产出物里有"未决分歧 + 所需信息"，收早了可以按 `DC-10` 带着新触发器重开；而多辩的轮次是不可回收的成本。

### 6.3 最小可决集（Minimum Decidable Set）

**DC-14｜"信息足够"不是感觉，是清单。** 一个议题的最小可决集 = 决策人做出这个决定所必需的最少信息。默认四项（可按议题类型裁剪，裁剪须写明）：

1. **结论方向与量级**（是什么、多大）。
2. **该结论的证据与口径**（数据来源 + 口径，可核验）。
3. **主要反对意见及其未被排除的理由**（不是"有人反对"，而是"反对什么、为何不能排除"）。
4. **决策选项与各自代价**（至少两个可选项，含"不做"）。

四项齐 = 可决 = 必须收口。**为"再充分一点"而追加轮次，是对决策人时间的浪费**。

## 七、共识分级与"带分歧交付"

### 7.1 共识四级

**DC-15｜共识分级，明确标注，不许含糊。**

| 级别 | 名称 | 含义 | 收口时的呈现 |
|---|---|---|---|
| **C0** | 无共识 | 连事实都没对齐 | 不允许收口到 P4（除强制收口，须标注） |
| **C1** | 事实共识 | 数据与口径一致，对"发生了什么"无争议 | `facts[]` |
| **C2** | 判断共识 | 对原因 / 结论方向与幅度看法一致 | `consensus[]` |
| **C3** | 行动共识 | 对下一步、责任人、验收标准一致 | `next_steps[]` |

**DC-16｜定案门槛 = C1 + C3，C2 非必须。** 允许"事实一致、判断有分歧，但下一步一致"——这在真实工作中极常见，也是最健康的收口形态。**要求先消灭判断分歧再行动，是把讨论拖成无终局的主要原因。**

### 7.2 带分歧交付与分歧登记表

**DC-17｜分歧不许被抹平，必须结构化登记。** 每条未决分歧登记以下字段，缺项视为收口不合格：

```yaml
- id: DIS-1
  point: 消费时长下滑主因是体裁结构 还是 新用户占比上升
  positions:
    - by: data              # 谁的立场
      stance: 体裁结构主导（视频 -14%）
    - by: ab-experiment
      stance: 新用户占比 +6pct 造成分母膨胀
  kind: fact                # fact | caliber | value（§6.1）
  why_open: 缺新老用户拆分后的体裁数据，无法归因排他
  need_to_resolve: 补一次「新老用户 × 体裁」交叉查询（约 1 次取数）
  impact: 影响结论方向（是否要动内容分发策略）
  owner: <决策人或下一场>
```

**DC-18｜多数不能压倒证据与红线。** 共识不是投票。3 个 Agent 的一致意见不能推翻 1 份数据，也不能推翻业务红线。主持人有义务在收口时显式指出"多数意见与数据/红线冲突"，并按数据与红线定案。

## 八、结束的三种语义：严格区分

**DC-19｜收口 / 叫停 / 终止是三件不同的事，产出物不同，不许互相代替。** 特别地：**不许用终止代替收口**——只要有部分结论，就必须走收口并交付部分结论。

### 8.1 收口（Close）：有产出的正常结束

产出物规格（缺项即不合格）：

| 字段 | 内容 |
|---|---|
| `verdict` | 有观点的结论（结论先行，方向 + 幅度） |
| `facts[]` | 已定事实（每条带来源 / 口径） |
| `consensus[]` | 共识点 + 达到的共识级别（C1/C2/C3） |
| `disagreements[]` | 分歧登记表（§7.2 全字段） |
| `decision_log[]` | 「我替你做的决定」：哪些是 Twin 代答、依据哪条规则 |
| `next_steps[]` | 下一步 + 责任 + 验收标准 |
| `refs[]` | 引用过的经验包 / 知识 / SQL / 数据指针 |
| `budget` | 用了几轮 / 几步 / 触发哪个收束触发器 |

### 8.2 叫停（Halt）：局部终止，场继续

适用：某条对话线跑题、循环、钻牛角尖，或某位发言者连续无增量。
**DC-20｜叫停必须带 `redirect`。** 只叫停不给新方向，等于把场悬空，下一步必然空转。叫停后的下一步只能是：换焦点 / 转动作（`ACT`）/ 收束。

### 8.3 终止（Abort）：无产出结束

**DC-21｜仅以下情形允许终止**，且必须留下"终止记录"：

| 情形 | 说明 |
|---|---|
| 红线 | 命中硬护栏且无合法降级路径 |
| 越权 | 需要越过隔离边界读写才能继续 |
| 依赖缺失 | 关键依赖不可用且无替代 |
| 决策人撤回 | 决策人明确终止 |
| 前提失效 | 目标所依赖的前提被证伪，议题本身不再成立 |

终止记录必须含：**终止原因 + 已获得的部分结论 + 恢复条件**（满足什么就能重开）。没有恢复条件的终止，等于把这段工作彻底扔掉。

## 九、Twin 检查其他 Agent 工作的专用标准（审查线）

这是本标准最需要严格的一段：**审查不是讨论**。讨论可以发散后收敛，审查必须有终局——否则就变成完美主义死循环，交付永远差一口气。

### 9.1 审查有限回合

**DC-22｜同一交付物最多打回 2 次。** 第 3 次不许再打回，必须在三条路里选一条并留痕：

1. **接受带缺陷交付**：交付 + 在交付物中显式标注缺陷与影响范围。
2. **升级决策人**：说明"两次打回未达标 + 缺口是什么 + 建议选项"（`escalate`）。
3. **换人换法**：换 Agent、换方法或拆小任务重派（`assign`），并说明为什么原路径走不通。

理由：同一交付物两次打回未过，通常不是 Agent 不努力，而是**任务定义、口径或能力匹配有问题**——继续打回是在错误的层面上使劲。

### 9.2 打回三可原则

**DC-23｜打回必须"可判定、可执行、可验收"，否则视为无效打回。**

| 要素 | 要求 | 反例 |
|---|---|---|
| **可判定** | 指明违反了哪条过关项（明确 id） | "感觉不太严谨" |
| **可执行** | 说清要补什么、按什么口径、查哪个维度 | "再深入一点" |
| **可验收** | 说清补到什么程度算过关 | "补充完整" |

**无效打回不计入 `DC-22` 的 2 次额度，但必须重写**——不能靠模糊打回无限续命。

### 9.3 一次申辩权

**DC-24｜被打回的 Agent 有且仅有一次申辩机会。** 申辩必须带证据或规则依据（不接受"我认为够了"）。Twin 必须回应申辩：**采纳**（撤销打回，并把该判据沉淀进经验/学习文件）或**驳回**（说明理由）。申辩后仍不一致，按 §6.1 归类处置：`fact` → 查数裁决；`caliber` → 查口径真相源；`value` → 升级决策人。

设立申辩权的原因：验收方同时是编排方，天然强势；没有申辩通道，Agent 的正确异议会被结构性压掉，而这些异议往往正是最有价值的信息。

### 9.4 裁判与教练的角色隔离

**DC-25｜Twin 不下场辩专业结论。** 主持 / 验收角色与"专家意见"角色不可混。Twin 若有专业质疑，正确做法是**把它变成一个带判定标准的焦点交给专家去判**，而不是自己下结论后要求别人认同。

**DC-26｜验收依据必须外化。** 每次打回都要引用具体检查条目。凭感觉打回不允许。若发现某类硬伤在清单里没有对应条目，先补清单（走记忆晋升审批），再用它打回——**先立规则，再执法**。

**DC-27｜验收只管正确性与完整性。** 文风、排版、措辞不进审查线（走 `beautify`）。对齐现有纪律：`rework` 只用于打回数据类交付，`beautify` 只用于排版，二者不混。

### 9.5 审查强度随信任等级变化

**DC-28｜审查不是恒定强度，随信任等级 L1–L4 调整**，但**红线项永不放松**：

| 信任等级 | 审查强度 | 打回额度 | 说明 |
|---|---|---|---|
| **L1 全程监工** | 逐条过全部检查项 | 2 次 | 默认档 |
| **L2 审计模式** | 全量过红线项 + 抽查其余 | 2 次 | 低风险项事后抽查 |
| **L3 例外管理** | 只过红线项 + 异常信号（数值离水位、口径不一致） | 1 次 | 无异常直接放行 |
| **L4 全权委托** | 只过红线项 | 1 次 | 非红线缺陷改为"标注后交付" |

**DC-29｜降级即回到 L1 强度。** 某类决策被连续纠正 3 次 → 该类型 `escalate_only`，其审查强度回到 L1，不受当前等级影响。

## 十二、留痕与可回溯

对齐文件为唯一真相源原则：**每一次判定都要能被复盘**，否则这份标准无法被验证是否真的在执行。

建议新增事件类型（追加式，向后兼容）：

| 事件 | 何时发 | 关键字段 |
|---|---|---|
| `focus_set` | 每次设定 / 切换焦点 | `focus`、`criteria`（判定标准）、`round` |
| `round_check` | 每轮末的三问判定 | `q1_open`、`q2_gain`、`q3_budget`、`decision`、`reason` |
| `gain_tag` | 每次发言判定增量 | `gain`（取值 E / A / R / C / 0）、`speaker` |
| `contention` | 登记 / 更新 / 关闭分歧 | `id`、`kind`（fact / caliber / value）、`status`、`why_open` |
| `review` | 每次验收 | `verdict`（pass / rework）、`criteria_ids[]`、`attempt`（1 或 2） |
| `appeal` | 申辩与裁定 | `by`、`grounds`、`ruling`（accept / reject） |
| `abort` | 终止 | `reason`、`partial_result`、`resume_condition` |

## 十三、落地分期

- **S1（低成本高收益）**：`DC-05` 焦点判定标准、`DC-03/04` 增量与空轮、`DC-06` 三问闸门、`DC-22` 打回 2 次上限、`DC-23` 打回三可。**只改 prompt + 少量计数器，不动架构。**
- **S2**：`DC-11` 分歧三分法（自动转 `ACT`/`ESCALATE`）、`DC-07` 强制小结、`DC-15~18` 结构化收口产出、`discussion.jsonl`。
- **S3**：`DC-24` 申辩、`DC-28/29` 审查强度联动信任、前端"判定链"可视化。

## 附 A：一页速查卡

**开轮前问三件事**
1. 焦点是一个吗？ 2. 它有判定标准吗？ 3. 上一轮有增量吗？——有一个"否"就别开轮。

**每轮末过三问（`DC-06`）**
Q1 还有未决分歧？ Q2 上轮有增量？ Q3 预算够再判一次？——任一"否"就前进（收束 / 转动作 / 升级 / 收口）。

**看到分歧先分类（`DC-11`）**
事实分歧 → **查数**；口径分歧 → **查规则**；价值分歧 → **问人**。**都不是"再辩一轮"。**

**收口门槛（`DC-16`）**
C1 事实共识 + C3 行动共识即可定案。判断分歧（C2）**登记**，不消灭。

**审查交付物（`DC-22/23`）**
最多打回 2 次；每次打回说清补什么、补到什么算过关；第 3 次改为"带缺陷交付 / 升级 / 换人换法"。

**三种结束（`DC-19`）**
`close` 有产出 / `halt` 停一条线 / `abort` 无产出——**有部分结论就必须收口，不许终止**。

---

> **一句话收束**：把"讨论到什么时候"从主观判断变成可判定的闸门——**焦点自带判定标准、发言必须有增量、分歧先分类再处置、可决即收口、审查有限回合、拍板只有一个人**。讨论的终点不是所有人都同意，而是决策人可以做决定，且分歧被诚实地记录下来。
